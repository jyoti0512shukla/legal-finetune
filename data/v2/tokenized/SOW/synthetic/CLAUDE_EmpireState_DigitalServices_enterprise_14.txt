ARTICLE 1 — PROJECT DESCRIPTION AND SCOPE

1.1 Project Objectives. The State Agency has engaged the Contractor to modernize the State Agency's permit application portal — the public-facing web application through which residents and small businesses apply for and renew permits administered by the State Agency. The objectives are to (a) replace the legacy mainframe-backed application portal with a cloud-native web application, (b) improve accessibility to comply with the Web Content Accessibility Guidelines (WCAG) 2.1 Level AA, (c) reduce average application completion time, (d) provide bilingual support (English and Spanish), and (e) preserve all data continuity and audit-trail requirements applicable to the State Agency under state records laws.

1.2 In-Scope Activities. The Contractor shall:

(a) Conduct a Discovery and Current-State Assessment, including stakeholder interviews, legacy system documentation review, and review of the State Agency's data classification policy.

(b) Produce a Target State Architecture Document and a Migration Plan.

(c) Build the new application portal as a cloud-native web application using the technology stack approved by the State Agency's Office of Information Technology Services (Schedule A).

(d) Migrate the historical permit data from the legacy mainframe system to the new application portal's data store, with full data validation and reconciliation.

(e) Implement the bilingual interface (English and Spanish) for all public-facing pages.

(f) Implement WCAG 2.1 Level AA compliance, with third-party accessibility audit and remediation.

(g) Implement role-based access controls for State Agency employees and integrate with the State Agency's enterprise single sign-on system.

(h) Implement audit trails and records retention controls compliant with the State Agency's records retention schedule.

(i) Conduct user acceptance testing in coordination with the State Agency's UAT team.

(j) Conduct end-user training for State Agency employees and produce written training materials.

(k) Provide a 90-calendar-day post-launch hypercare period.

1.3 Out-of-Scope Activities. The following are out-of-scope under this SOW. Any of the following, if requested, requires a Change Order under Article 8:

(a) Modifications to the State Agency's enterprise single sign-on system. The Contractor integrates with the existing system as is.

(b) Modifications to the State Agency's existing payment processing infrastructure. Permit fees are processed through the State Agency's existing payment infrastructure.

(c) New permit programs or new permit types not currently supported by the legacy system.

(d) Modifications to the State Agency's enterprise data warehouse beyond delivering data extracts in the State Agency's standard format.

(e) Modifications to the State Agency's internal case management systems.

(f) Any work product subject to U.S. export-control restrictions.

(g) Translation services into languages other than Spanish.

(h) Print fulfillment, mail handling, or any non-digital services.

1.4 Engagement Period. The Contractor shall perform the In-Scope Activities during the period beginning on the Project Start Date and ending on the Project End Date set forth in Article 3.

ARTICLE 2 — DELIVERABLES AND ACCEPTANCE

2.1 Deliverables. The Contractor shall produce and deliver to the State Agency the following deliverables:

(a) Discovery and Current-State Assessment Report. Target: end of Project Week 6.

(b) Target State Architecture Document and Migration Plan. Target: end of Project Week 12.

(c) Iteration Build Releases — six (6) iteration builds delivered to the State Agency's UAT environment over Project Weeks 16 through 36, with each build implementing a defined set of user stories from the Migration Plan.

(d) Data Migration Validation Report — written report documenting the historical data migration and the reconciliation results. Target: end of Project Week 38.

(e) Accessibility Audit Report — third-party WCAG 2.1 Level AA audit results and remediation status. Target: end of Project Week 40.

(f) Bilingual Implementation Validation — written validation that all public-facing pages support both English and Spanish. Target: end of Project Week 40.

(g) UAT Sign-off — signed UAT acceptance from the State Agency's UAT team. Target: end of Project Week 42.

(h) Production Cutover Implementation and Cutover Report. Target: end of Project Week 44.

(i) End-User Training Sessions and Training Materials. Target: end of Project Week 45.

(j) Hypercare Closure Report covering the 90-day hypercare period. Target: end of Project Week 58.

(k) Records Retention Documentation evidencing the new system's compliance with the State Agency's records retention schedule.

2.2 Acceptance Criteria. Acceptance criteria for each Deliverable are set forth in Schedule B. The State Agency reserves the sole right to determine whether each Deliverable satisfies the acceptance criteria.

2.3 Acceptance Period. The State Agency shall have a period of twenty (20) business days following its receipt of each Deliverable to review and notify the Contractor in writing of acceptance or rejection. The State Agency may extend the Acceptance Period for any Deliverable that requires review by the State Agency's Office of Information Technology Services or any other state oversight body.

2.4 Cure of Non-Conformity. If the State Agency rejects a Deliverable, the Contractor shall correct the alleged non-conformity at no additional charge and resubmit the corrected Deliverable to the State Agency within fifteen (15) business days. The State Agency shall then have a new Acceptance Period to review the resubmitted Deliverable. If the Contractor fails to deliver a conforming Deliverable after two (2) cycles of cure, the State Agency may, at its sole option, (i) accept the Deliverable in its then-current form with an equitable reduction in the Project Fee, (ii) terminate this SOW for material breach pursuant to the termination provisions of the MSA, or (iii) require the Contractor to engage at the Contractor's expense a third-party developer reasonably acceptable to the State Agency to complete the rejected Deliverable.

2.5 No Deemed Acceptance. There shall be no deemed acceptance of any Deliverable under any circumstances.
